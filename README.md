# vibe-start-pack

Компактные инструкции для команд и AI-агентов: быстрее находить нужный контекст, сохранять решения и продолжать работу между задачами и чатами.

В проекте действуют три роли:

| Роль | Задача | Модель по умолчанию |
|---|---|---|
| **Architect** | Понимает запрос, исследует проект, принимает существенные решения, распределяет работу и принимает результат. | Наиболее сильная подходящая из доступных. |
| **Implementer** | Реализует согласованную задачу в заданных границах и обновляет затронутые документы. | Подходящая из проверенного Flash-пула. |
| **Validator** | Независимо проверяет согласованный результат и сообщает фактические доказательства. | Для AI-валидатора — подходящая из проверенного Flash-пула. |

Flash-пул — быстрые экономичные модели, доступные в выбранной среде. При настройке агент проверяет состав пула и фактическое назначение моделей; автоматического наследования сильной модели архитектора недостаточно.

Порядок работы: **Architect → Implementer → ревью Architect → Validator → приёмка и обновление контекста.** Внутри роли можно параллельно вести независимые задачи с отдельными границами. Для передачи работы родитель указывает явную роль, корень проекта и путь к проектным инструкциям. Инструкции из верхнеуровневого чата не считаются автоматически полученными дочерним агентом.

## Начало работы

1. Скачайте набор в отдельный каталог домашней папки:

   ```sh
   git clone https://github.com/nagiyevstudio/vibe-start-pack.git "$HOME/vibe-start-pack"
   ```

   Команда скачивает файлы набора. Не помещайте весь репозиторий кита в приложение и не заменяйте его прикладной README.
2. Откройте целевой проект в среде агента. Дайте агенту доступ к файлу кита и поручите ему прочитать [SKILL.md](SKILL.md). Прямое чтение файла подходит среде с доступом к файлам; автоматическая установка в каждый клиент не предполагается.
3. Передайте агенту один из запросов ниже. `~/vibe-start-pack` — каталог, созданный командой выше; целевой проект — открытая в среде агента папка.

**Новый проект:**

> Роль: Architect. Прочитай `~/vibe-start-pack/SKILL.md` и подготовь текущую папку как новый проект к работе по этому набору. Сначала помоги мне определить пользователя, первый полезный результат и важные ограничения. Неизвестное явно отметь; не создавай продуктовый код и инфраструктуру.

**Существующий проект:**

> Роль: Architect. Прочитай `~/vibe-start-pack/SKILL.md` и примени набор к текущему существующему проекту. Изучи текущие инструкции и документы, сохрани локальные изменения, встроись в существующие источники истины и не создавай дубликаты.

В начале настройки агент проверяет фактические возможности своей среды. Наличие верхнеуровневых инструкций ещё не подтверждает, что дочерний агент получил и прочитал инструкции проекта. Кит просит проверить запуск ребёнка и передачу ему актуального проектного файла раздельно; если проверка недоступна, статус остаётся неподтверждённым.

Для обновления скачанного набора:

```sh
git -C "$HOME/vibe-start-pack" pull --ff-only
```

Чтобы применить обновление к проектным инструкциям, повторите запрос агенту: настройка сохраняет существующие документы и пользовательские правки. Развёртывание сервера для этого набора не требуется.

## Как устроен набор

Пять файлов ниже — стандартные роли документов, а не обязательный список для каждого проекта. При установке обычно используется корневой `AGENTS.md` и папка `docs/project/`. Если у проекта уже есть карта, текущий статус, журнал решений или документация изменений, агент должен дополнить её и сослаться на неё вместо создания второй системы.

| Шаблон кита | Назначение |
|---|---|
| [AGENTS.md](templates/AGENTS.md) | Выбор роли, рабочий процесс и короткий индекс контекста. |
| [CONTEXT.md](templates/CONTEXT.md) | Цель проекта, карта кода и подтверждённые сведения о среде. |
| [STATE.md](templates/STATE.md) | Активная задача, её владелец, блокеры и следующий шаг. |
| [DECISIONS.md](templates/DECISIONS.md) | Долговечные принятые решения и причины. |
| [DEVLOG.md](templates/DEVLOG.md) | Краткие значимые завершения и фактические результаты. |

Новая задача или новый чат начинаются с проектного `AGENTS.md`; затем читаются только относящиеся к задаче части карты и состояния. В `STATE.md` различаются предложенное, принятое, реализованное, проверенное и выпущенное. Принятие решения не означает реализацию, а реализация не подтверждает проверку или выпуск.

Новые и изменяемые зависимости проверяются по актуальным официальным документам и реестру, совместимости с runtime и lockfile. Повторная настройка сохраняет пользовательские правки и прежние блокеры. Справку пользовательского интерфейса обновляют, если проект уже ведёт такую документацию; файл на каждую кнопку не нужен.

## Проверка и границы

2 ноября 2026 года один сквозной сценарий прошёл на синтетическом Python-проекте в OpenCode с MiMo v2.6 Pro: передача задачи, чтение проектных инструкций дочерним Implementer-ом, ограниченная реализация, отдельная проверка и ревью Architect-а. Совместимость с другими клиентами, моделями и настройками этим результатом не установлена; установочный skill проверяет фактическую среду проекта.

Раздельный выбор Flash-моделей для Implementer и Validator в этом прогоне не проверялся.

## Вклад

Сообщая о проблеме, укажите клиент и версию, модель и провайдер, запрос, ожидаемое и фактическое поведение. Уберите ключи, личные данные и другие секреты. Изменения предлагайте небольшими и в пределах инструкций; не добавляйте новые роли или документацию без необходимости.
