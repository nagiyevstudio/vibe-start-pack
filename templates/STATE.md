## Статус результата

Для текущего этапа указывай каждый применимый статус отдельно. Подставляй ссылку на evidence или пиши «не проверено»; не подразумевай статус из соседней строки.

| Состояние | Факт / свидетельство |
|---|---|
| Предложено |  |
| Принято (что и кем) |  |
| Реализовано (или частично, с блокером) |  |
| Проверка (ожидается / PASS / FAIL / BLOCKED + evidence) | Не проверено |
| Выпущено / развёрнуто + evidence | Не проверено |

При каждом handoff обновляй роль, контур и применимые статусы. Перед отдачей Implementer на ревью явно зафиксируй «реализовано, проверка ожидается» либо частичное выполнение и блокер. `Реализовано` не означает `Проверено`; принятие не доказывает выпуск. Не подразумевай разрешение или одобрение пользователя для каждой обычной задачи; фиксируй запрос только если решение действительно требуется. Удаляй закрытые детали из текущего снимка, сохраняя долговечные решения в `DECISIONS.md`, а важные завершения — в `DEVLOG.md`.
